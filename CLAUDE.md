# NurtureTrack (IS216, group Cocomelon, G9)

Dual-user postpartum web app for two parents (Daniel and Mei). Graded by a dad, so it must feel calm and useful at 3 AM.

## Stack
Vue 3 + Vite, Pinia, vue-router, Bootstrap 5 (installed), Firebase (Google sign in, Firestore), Vercel, FCM push, Google Calendar API. Package manager: pnpm.
Use Bootstrap utilities and CSS variable overrides in `src/assets/styles/main.css`. Do not add Tailwind.

## Design source of truth
Figma file: https://www.figma.com/design/EQ8l3puqd2k146elsbasST (key `EQ8l3puqd2k146elsbasST`), page "Main Flow".
Build from **Prototype B: Preline UI kit** only. Prototype A is the old design, ignore it.
Read each frame with the Figma MCP `get_design_context` (load the figma-design-to-code skill first). Frame IDs and routes are in `docs/design.md`.
The Preline kit is Tailwind-based. Copy its look (spacing, radii, borders, badge and button styles) into Bootstrap, do not copy its classes.

## Design tokens
- Plum `#3B2F3F` (primary, one solid plum button per screen), page bg `#FDFCFB`, ink `#1F2937`, muted `#6B7280`, line `#E5E7EB`
- Daniel apricot `#F6D8C6` / `#E3A584`, Mei powder `#DCE6F2` / `#5C7A9E`
- Butter `#F5E7B8` with dashed border `#6F5F3A`: ONLY for "Yours alone" private content
- Coral `#C0553B`: the "Now" marker and unseen items. Yellow only for warnings. Red soft only for urgent medical notes.
- Soft badges: Feed blue `#DBEAFE`/`#1E40AF`, Nappy teal `#CCFBF1`/`#115E59`, Sleep gray, Medication and Note outlined
- Fonts: Young Serif for page titles and card headings, Inter for everything else. Body text 14px minimum.
- Radii 8 for inputs and rows, 12 for cards. 1px `#E5E7EB` borders, no shadows.

## Signature pieces to keep
- The night strip (6 PM to 6 AM bar, feed ticks, coral "Now" line) on Landing and Home.
- The butter dashed "Yours alone" box. Anything private to one parent (check-in, confidence rating) uses it, and the other parent never sees that data.

## Product rules
- Minimise free text inputs. Prefer taps, choice rows, scales.
- Plain, warm copy. No em dashes. Sentence case. Buttons name the action ("Save entry", not "Submit").
- Medical and helpline content is general guidance only. Sample data is labelled as placeholder. Verify Singapore helpline numbers, doctor thresholds and mall addresses before demo.

## Repo layout
`api/*.js` are the Vercel serverless functions (one default export `(req, res)` each), with shared modules in `api/_lib/` which Vercel does not route. `vercel.json` sets the Vite build and a 60 second function limit. Server only secrets are the names without a `VITE_` prefix in `.env.example`; `docs/setup.md` is the setup guide.
`src/pages/<name>/index.vue` per page, with `components/`, `composables/`, `shared/` beside it. Shared UI in `src/components/common` and `src/components/layout`. Routes in `src/shared/constants/routes.js`. Auth in `src/composables/useAuth.js` and `src/api/`.
The old scaffold UI was deleted and rebuilt from Figma Prototype B. One folder per page in `src/pages/<name>/index.vue` (24 pages, names match `src/shared/constants/routes.js`). Shared UI lives in `src/components/ui/`, layouts in `src/layouts/`, sample data in `src/data/`, onboarding state in `src/stores/household.js`. Real Google sign in is wired through `src/composables/useAuth.js`; everything else uses sample data until Firestore is added.

## Working agreement
Branch per feature (`dev/<initials>/<feature>`), small commits, run `pnpm lint` and `pnpm test:unit` before pushing. Build in the order listed in `docs/design.md`.

App update: the account and household layer is built. Two new pages sit inside the shell with the same guard as Home and are deliberately not in the nav: `/profile` (display name, role chips Mum, Dad, Carer, read only email with the sign in method) and `/settings` (notifications, Google Calendar, display, privacy, partner, household, danger zone). Settings has no solid button at all: every control saves itself after about 600 ms with a quiet "Saved", each field under its own dotted path so two sections never overwrite each other. The display choices are real, not decoration: `src/app/composables/usePrefs.js` feeds the calendar's week start and the care log's time rendering. Invitation codes now expire after seven days and carry `usedAt`, `usedBy` and `revokedAt`, so joining with a dead code says why ("That code has expired. The pumping room directory moved out of localStorage into the top level collection `pumpingRooms` with reports underneath it, shared by every household, with the two rooms in `src/app/data/pumpingRooms.js` kept as clearly labelled seed data shown only while the collection is empty; the Support page gained "Confirm this room" and "Flag as gone". "Delete my account" and "Leave household" sit behind a typed DELETE or LEAVE in an outline button with coral text, and deletion calls `/api/account/delete` through the thin client in `src/api/server.js`, falling back to a browser side best effort that is honest about what it could not remove (`docs/account-deletion.md` has the procedure the server must implement). `src/app/utils/limits.js` holds a sliding window in localStorage (5 room reports, 10 entries, 3 invite regenerations, 3 deletion attempts per 10 minutes) used by room reports, invite regeneration and deletion attempts; it is a courtesy guard, and the rules now cap the user supplied string lengths and require `request.time` on rooms and reports so a flood is at least attributable. `.env.example` lists the Firebase keys plus `VITE_FIREBASE_VAPID_KEY` for later; `src/api/firebase.js` still holds the config inline because it is a V2 file. See `docs/app.md` and `docs/data-model.md`.

App update: the server side is built, as six Vercel serverless functions under `api/` with Firebase Admin and `googleapis` (`firebase-admin` 14.5.0 and `googleapis` 182.0.0 are pinned in `package.json`). `GET /api/health` reports which environment variable groups are set and never their values; `GET /api/google/connect` and `GET /api/google/callback` run the OAuth consent flow with a signed, five minute, single use `state` value and store the refresh token in `googleTokens/{uid}`; `POST /api/google/disconnect` revokes it; `POST /api/google/sync` syncs `households/{hid}/events` both ways with a secondary Google calendar called "NurtureTrack"; `POST /api/account/delete` runs the procedure in `docs/account-deletion.md`, anonymising entries, events and tasks to "A parent" and deleting the household when the leaving user was its last member. Shared helpers are in `api/_lib/` (`admin`, `auth`, `respond`, `rateLimit`, `limitWindow`, `google`, `state`, `calendarMap`, `batch`); the pure ones are unit tested. The conflict rule is "whichever side was updated later wins", a tie going to NurtureTrack, and timed events carry an explicit "Asia/Singapore" time zone. Deletes need no tombstone collection: the server keeps its own map of what it pushed in `googleSync/{uid}.pushed`. Four top level collections (`googleTokens`, `googleSync`, `oauthStates`, `serverLimits`) are denied to every client in `firestore.rules`, because only the Admin SDK touches them, and `serverLimits/{uid}` holds the real per uid rate limits (3 deletions, 10 connects, 20 syncs per ten minutes) behind the courtesy guard in `src/app/utils/limits.js`. On the client, `src/api/server.js` now sends `Authorization: Bearer <ID token>` on every call and gained `syncGoogleCalendar`; Settings reports the `?calendar=` flag the callback redirects with, cleans it out of the address and has a "Sync now" outline button while connected; the Calendar page shows one muted "Synced with Google Calendar" line. **Push notifications are still not built on purpose**: no FCM, no service worker, no `firebase/messaging` import anywhere, and the notification preferences in Settings are saved and untouched. `VITE_FIREBASE_VAPID_KEY` is the variable push will need. See `docs/setup.md`, `docs/app.md` and `docs/data-model.md` section 7b.
